# 根据现象定位

| 现象 | 下一步 |
| --- | --- |
| `accessibilityGranted=false` | 给输出路径中的键盘 App 授权；不要把 Terminal 的授权当作这个 App 的授权 |
| `screenCaptureGranted=false` | 显式请求屏幕录制授权，按系统提示处理宿主；不要更改 SIP 解决截图权限 |
| 找不到目标窗口 | 确认微信已登录、有可见主窗口；最小化、锁屏和无显示环境未验证 |
| 多个微信进程 | 报告歧义，让用户选择处理；工具不擅自退出实例 |
| `wechat_not_frontmost` | 在允许前台操作时激活微信，再截图；不向后台盲发文字 |
| 截图是白的 | 比较 direct、stream、app 三种输出；记录版本和窗口。两种都成功不能证明 stream 切换修复了白屏 |
| 搜索文字出现，但没有结果 | 看 `03-app-windows.png`，下拉框可能属于另一个应用窗口；若仍未加载，等待后再截 |
| 标题变化但聊天像没切换 | 等待并重新截图，内容可能尚未加载，不能马上发消息 |
| 用户在过程中操作电脑 | 以新截图重新建立状态；不依赖之前的焦点假设 |
| 输入或发送超时 | 先查看已有草稿和聊天尾部；不得不加核对地重复输入/发送 |
| 回车后仅换行 | 用户可能更改发送快捷键。本版未适配所有配置；保留草稿，报告，不盲试组合键 |

不要直接把空白截图、无障碍树缺失、后台无焦点、输入拒绝和发送失败统称为“微信反自动化”。本版依赖图像观察，不要求完整 Accessibility tree；键盘投递日志仅代表工具调用完成。

这套工具检查的是进程数量、权限及前台状态，**它并不识别收件人**。收件人与正文必须由 Agent 读取新截图核对。截图与按键之间没有原子锁，用户和其他自动化都可能改变 UI；执行任务时避免并行控制同一个微信窗口。
