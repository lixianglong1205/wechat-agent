## SIP 事实

取钥与离线解密是两步。历史中的 SIP 调整发生在前者。后来的桌面发送使用辅助功能和截图能力，没有在发送测试中调整 SIP；测试机器当时仍为 SIP disabled，不能宣称验证了 SIP enabled 下的完整发送链路。

本文引用的上游新取钥路线描述了 SIP enabled 的独立调试副本方案。来源提交为 `712bc9637f948ac1eedce73ff585e6d3d672fa06`，提交日期 2026-10-03。这是上游状态，不是本机执行记录，不能与旧原型混写成一条已复现路径。

## 截图事实

直接窗口截图和更新过滤器后的 stream 都正常，因此无法证明白屏由某个过滤器 bug 或重复安装微信引起。增加同应用窗口截图是为了解决搜索下拉框不在主窗口截图里的问题。

## 公共封装的验证范围

首次公开版本把已验证的 Swift 动作封装成可移植 Skill，增加构建缓存、私有输出目录、前台检查和上下方向键。公共版本在开发机完成两份 Swift 源码编译、ad-hoc 签名校验、构建缓存复用、实际权限状态检查，以及三种截图输出和同应用窗口截图的人工查看。未为测试公共封装再发额外消息。

5 项离线测试通过：控制字符/多行输入在事件投递前被拒绝；临时消息文件为 0600 且成功/失败后均删除；前台激活要求明确参数；运行目录不能位于 Git 仓库；公共文件检查器拒绝数据库路径、截图、二进制和合成凭据。Skill 格式校验和文档相对链接检查也已通过。

新包身份与原型测试包不同，其他机器首次运行仍需自己的系统授权。原型成功发送不能替代每位使用者在自己机器上的自发测试。

尚未单独验证：SIP 开启时的完整 UI 发送、锁屏/无显示器运行、不同语言和布局的全部微信版本、通过自建手机客户端远程发送。
